SHARC peripheral control-register bridge

PGRrev2.4 7-7/8 distinguishes core IOP registers from peripheral IOP registers.
Peripheral writes accept the actual CPU source value, then deliver it after
4..5 CCLK. The first store accepts in one core cycle; continuous subsequent
stores have two-CCLK spacing. Other core instructions can execute before the
peripheral sees a posted write. A peripheral read drains prior writes, then
captures actual target data after7..8 CCLK. Immediate back-to-back reads need
eight clocks. A write/read pair therefore takes11..13 CCLK. These are primary
control-register bounds, not permission to assume FIFO or buffer readiness.

SharcIopBridge is a MemoryDevice mapped in the core's SharcMemory. A separate
SharcMemory maps real peripheral devices. issue supplies the actual instruction
PC, operation, logical word address and an explicit documented latency input.
The normal core instruction supplies store data through its real transaction;
no host value is substituted. A read response comes from one actual peripheral
transaction and remains cached until the exact core request retires. Zero is
valid data. A later CPU fault rolls back token consumption, preserving an
already completed external read without replaying its side effects.

The owner advances one elapsed CCLK with tick. At delivery, backend accesses
have the issuing PC and normal word-address/operation diagnostics. A failed
transfer aborts its target transaction, retains the elapsed clock and due
request, and rejects further clocks until retry_due succeeds. Already retired
core instructions are not rolled back for a later posted-store failure.
retry_due adds no elapsed time. Foreign transactions cannot be stolen.

The fixed four-entry array is a storage bound, not an asserted silicon FIFO
depth. Snapshots retain posted values, original PCs, timestamps, read start
and any captured response; backend/core snapshots remain separately owned.
Restore checks request pairing, queue continuity, timing and history. Clock
events, issue and snapshots reject active transactions. Normal queue/clock
operations use fixed state and do not allocate.

SharcIopPort exposes a disjoint core mapping inside the same bridge span.
It translates relative byte offsets to the bridge's logical address domain;
it has no separate queue, clock or response. Thus a DPI read drains earlier
DAI writes, and a port cannot consume another port's response. Each view
maps once and shares the bound core's transaction; multiple peripheral
accesses inside a single unqualified CPU transaction still reject. Invalid
view spans, offsets, widths and construction during a transaction reject.
Core/backend/port mappings must be restored together with the bridge state.

When composing a core/PCLK ratio of2 with PMCTL1 and DAI effects, advance the
elapsed half-PCLK interval before tick delivers a new write. A write arriving
on that edge must not age during the interval preceding its arrival. The
half-period APIs retain fractional progress per pending write, including
across snapshots and mixed full/half-period calls.

The bound fetch transport previews the actual Execute word without reading
peripheral data or rereading instruction RAM. The qualified subset is an
unconditional32-bit DM transfer through DREG0..15 or USTAT1/2. A core hold
requires the exact pending PC/address/operation and the actual mapped bridge
or matching port. It retains every pipeline/IAB field and guest PC while
maturing supported delayed CPU/SYSCTL effects. No guest NOP is synthesized.
The owner advances devices separately; read retirement shares its final
response clock, while a spaced write still uses its own acceptance clock.
A failed due transfer needs retry_due, not another core hold. Snapshots retain
existing CPU, fetch and bridge state without a new hidden wait counter.
Mode/branch/cache/loop/interrupt compositions outside this subset reject.

Open: exact physical phase selection for4/5 and7/8, independent prefetch/DMA
arbitration during IOP holds, general five-stage peripheral scheduling,
conditional/aborted IOP timing, buffer/FIFO hangs and BHD, complete SRU/
peripheral coupling and physical board clocks.
Supplying a latency within documented bounds is an explicit reference input,
not a measured Nord phase or a completed board scheduler. Core IOP addresses
at/above30000 are deliberately outside this peripheral bridge. Unsupported
target registers still fail through the real backend.

The full instrument objective remains unchanged. Passing component checks or
an instruction-order original prefix does not prove cold boot, audio or USB.
Primary document identities are pinned in reference/sharc.json.

Owned tests execute real native stores/loads, source capture followed by core
work, continuous posted stores, both read/write bounds and11..13-clock atomic
pairs. They check independent literal values, cached zero/nonzero responses,
real CPU token rollback after target capture, late target read/write faults,
no-clock delivery retry, queue/response restores and malformed ownership,
requests and snapshots. A real DAI read/mask/OR/store/read composition advances
effect intervals before deliveries, including a half-period arrival.

The separate original_sharc_clocked_iop profile continues the real common-call
return into the second CALL and application initialization through the bound
five-stage native/VISA transport. PMCTL1 is posted through the same queue as
DAI/DPI. Each elapsed half-PCLK precedes newly due deliveries. This profile
starts a stated local clock epoch after the common call and supplies5/8-clock
inputs; earlier native/core-IOP/PMCTL timing and physical Nord phase remain
separate gaps. It neither runs the functional fork first nor seeds its device
state from that fork. All eight placements/cadences retire95 further actual
instructions:18 power/modifier,64 routing/PP_CTL, twelve SRU2 PIN0/PBEN0 RMW
instructions and compact zero USTAT1. The first PIN0 read now succeeds at217
local CCLK. Static original fields and PGR short-compute semantics establish
each R0/R1 intermediate, PC/width and real posted target/value independently.
The explicit family reset words are restored idempotently (sharc-dpi.txt).
After95 instructions the local epoch is240 CCLK:95 retirement clocks, six
refills, thirteen seven-clock read extensions and twelve four-clock posted
drains. The final PBEN0 store remains genuinely posted. The next actual
SPIDMAC1084 store at second-CALL target+207 is guarded because the existing
SPI DMA mapping is not yet bound through this timed bridge. CPU/IAB/queue,
SPI and both routers remain unchanged by that failure. No immediate-success
fallback, extra guest polling or SPI reset is supplied. This is not a physical
Nord timing measurement or complete original startup.
