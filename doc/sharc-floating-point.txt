SHARC finite floating add/sub reference

Primary evidence: Programming Reference rev2.4,3-37..39,11-24/25,
12-4/Table12-4,A-5,A-17..23,C-1..3. Manufacturer manuals remain local;
reference/sharc.json records provenance. No private implementation is used.

sharc_float_add operates on packed40 register bits using integer arithmetic
only. The format has one sign bit, eight exponent bits and31 stored fraction
bits with a hidden leading one. RND32=1 selects24 significant bits, clears
the low8 INPUT bits before arithmetic and returns eight zero output bits.
RND32=0 selects32 significant bits. This follows A-5's explicit bit definition;
3-37's introductory parenthetical equating RND32=1 with extended precision
conflicts with its following description and is not followed literally.
TRUNC selects toward-zero; otherwise halfway values round to an even LSB.

The independent finite numeric engine handles exponent alignment, addition,
subtraction, cancellation, normalization, sign and rounding carry. Three
retained guard/round/sticky bits preserve discarded nonzero data across
large exponent differences. Close cancellation retains all relevant bits.
All shifts and intermediates fit unsigned64; no host float/double/long double,
process floating environment, SSE/AVX instruction or host exception flag is
used. There is one final rounding at the selected precision.

Denormal inputs flush to signed zero. Exact opposite-sign cancellation returns
+zero under both supported rounding modes; two effective negative zeros return
-zero. Post-rounded tiny nonzero values flush to signed zero with underflow
metadata. Post-rounded overflow returns signed infinity for nearest/even or
the format's largest finite magnitude for toward-zero, with overflow metadata.
These metadata describe numeric range outcomes, not ASTAT/STKY or a routed
arithmetic interrupt. NAN/infinity inputs, bits above40 and invalid formats/
rounding enums reject. The numeric engine is not a complete floating unit. Shared numeric results use
SharcFloatResult; finite multiply is in sharc-floating-multiply.txt.

Native integration

Type2a ALU opcodes81/82 now execute floating addition/subtraction when the
rounded result is normal and nonzero. Effective MODE1 supplies both rounding
controls and their existing one-instruction latency. Required input bits must
be known; RND32 may ignore unknown low8 extension bits. Both inputs are read
before an in-place destination write. The result establishes all40 bits.
AF is set, AN follows the normal result sign, AZ/AV/AC/AS/AI clear. Other
ASTAT bits and all STKY bits/knowledge remain unchanged. SISD executes PEx;
SIMD conditions and low/high alternate data banks retain the existing
independent per-element selection. An inactive element does not read missing
inputs or rounding controls. This is scalar host reference execution, not
host SIMD acceleration or instrument-slot allocation.

Native zero/underflow/overflow results and NAN/infinity inputs explicitly fail
before instruction commit. In particular, the unresolved AUS interpretation
for exact zero, AN for -zero/NAN and NAN payload under RND32 are not inferred
from host comparisons or another SHARC generation. PGR11-24/25 and A-23 call
AUS a sticky indicator of AZ, while AZ includes exact zero and tiny results;
further primary/stock-silicon evidence is requested in the private issue.
Arithmetic exception routing and recurrence remain unqualified. These cases
must become faithful native execution before complete FPU/application acceptance;
keeping a numeric result alone does not fulfill that requirement.

The native instruction transaction stages CPU, memory and controller effects.
A missing second SIMD input, unknown rounding mode or guarded later lane keeps
the original data/status/PC/pending controls and external ownership intact.
No zero, infinity, silent success or guessed flag substitutes for a fault.
Existing generic compute dispatch can reach this arithmetic in count loops
and register-move compositions; complete parallel/multifunction/load hazards
still require their own evidence and tests.

Evidence

sharc_finite_floating_alu checks independent literal packed-bit oracles:
exact sums/differences, both signed zeros, denormal flush, halfway even/odd,
above-half/toward-zero, input extension clearing, postround tiny and signed
overflow bounds, including the largest-finite/half-ULP crossover. Native
toward-zero retains the largest finite value without a postround overflow
when the unrounded exact sum lies just beyond that value. Actual native words
qualify both effective rounding controls,
positive/negative flags and STKY preservation, unknown discarded versus required
extension bits, all four per-PE condition combinations, in-place writes,
alternate banks, pending MODE1 latency and whole-step fault rollback.
Parallel register transfers preserve old full40 source values and win over
a conflicting floating destination write. Dual DM/PM loads retain old
floating inputs, preserve DM-load precedence and roll back preceding stores
when floating input validation fails. False conditions skip unknown
rounding controls/inputs; unknown floating X-X is not simplified to zero. An actual
five-iteration floating accumulation executes through SharcFetch, then resumes
from independently rebound CPU/transport/RAM after the second body. Each result
2,3,4,5,6 and final PC/frame is checked independently.

sharc_float_exact_oracle derives460800 owned deterministic cases using Python
Fraction. It forms exact rational operands/sums, chooses the result exponent by
integer bit lengths and rounds the rational quotient once. It shares no C++
shift/jam/normalization implementation. A fixed Cartesian grid covers both
formats, both rounding modes, add/sub, all signs, ten exponents and twelve
fractions including low8 input boundaries. The C++ test checks every packed
result and range outcome, with an exact expected case count. This is finite
regression coverage, not random/fuzz testing, original DSP execution or a
physical-silicon comparison. Literal vectors supplement the generated oracle.

Remaining FPU scope includes exceptional native status/interrupts, NAN/infinity
inputs, other ALU operations and conversions, multiplier/accumulators,
multifunction, VISA, operand/pipeline hazards and full DSP application/audio.
Bounded floating multiplication now has the separate sharc-floating-multiply.txt
contract; full multiplier/accumulator coverage remains open.
The loader's integer paths do not qualify floating synthesis or real-time speed.
