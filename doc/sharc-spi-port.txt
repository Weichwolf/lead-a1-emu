Shared SHARC SPI control, buffers and receive DMA

SharcSpiPort maps logical IOP words1000..1084 to one existing SharcSpi
instance. SPICTL1000, TXSPI1003, RXSPI1004 and the existing DMA1080..1084
share serial state and one transaction. Unsupported registers/holes fail
through SharcMemory with operation, logical address, PC and width.
The legacy DMA-only facade remains available for existing reference fixtures.

The functional control subset is enabled, slave, LSB-first32, CLKPL1/CPHASE1,
TIMOD0 receive-core or TIMOD2 receive-DMA. SENDZ, GM, ISSEN and DMISO retain
their register bits; ISSEN does not change slave-select behavior in slave mode.
Changing control requires no partial word, active DMA or outstanding FIFO burst.
Enable/format/master/transmit-DMA changes, SPISTAT/W1C, flags, baud, shadow,
flush, chaining and interrupted words remain explicit gaps, not successful stubs.

Falling serial edges load/shift TX data; rising edges sample MOSI. TXSPI is a
single buffer independent of the active shift register. A later TXSPI write
queues the next word. Empty TX sends zeros with SENDZ, otherwise the retained
last data; unknown last data remains unknown and cannot be returned as a known
MISO level. DMISO or an inactive slave select disables the modeled output.
Full-buffer overwrite/collision behavior is guarded. This logical signal is
not a package pin or qualified Nord MISO wiring.

Accepted RX words update the receive buffer/data latch. GM0 discards a new
word if that buffer is full; GM1 overwrites it. Core RXSPI reads clear the full
condition but preserve the data latch. The initial handoff latch is unknown
until an observed word establishes it. DMA FIFO contents, cursor, count,
serial alignment and pending receive data survive the application mode change.
Core mode does not service the old DMA FIFO. TIMOD0 asserts a held RX-full
request; acknowledging a peripheral event alone cannot clear that level.
INTERR selects receive overflow or transmit underflow according to SPIRCV.
Pending DMA events, error requests and the processor's IRPTL remain distinct.

Primary reference: ADI ADSP-214xx HWR rev1.1,3-10/11,16-15..22,16-32..39,
A-223..229; pinned manual provenance is in reference/sharc.json.
This is a functional reference, not qualified SPI register-effect timing.
HWR16-34's2-PCLK enable/disable effect and A-225's2-CCLK disable-buffer flush
are separate from the core IOP delivery latency; unsupported enable changes
cannot bypass either requirement. Full board/global timing remains open.

The owned sharc_spi_control_buffers test uses literal independent32-bit MOSI/
MISO words, both phases including the final bit, queued TX and SENDZ, GM0/GM1,
unknown input state, held interrupt requests, retained DMA data, actual MMIO
abort/retry and malformed accesses. Actual fetched CPU/IOP tests cover all
four4/5-write7/8-read combinations, late target failure and no-time retry.
Original DSP and coupled ARM/SPI prefix regressions retain their independent
payload/control assertions. The original application's timed SPI binding,
complete startup and physical board behavior remain open.
