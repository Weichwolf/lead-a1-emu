Functional TI-family interrupt-controller reference

Evidence and scope
Original ARM0 operands identify base 0xfffee000, SICR +0x24, HIPIR +0x900/904,
HINLR +0x1104 and HIPVR +0x1600/1604. These match pinned SPRUH82C chapter 11.
The implementation uses zero-based host indices: 0=FIQ, 1=IRQ. The manual calls
the corresponding host registers 1/2. This correspondence does not identify the
exact Nord SoC/revision, reset state, clocks, peripheral event wiring or board.

Aintc requires explicit input state. reset_reference() supplies the documented
AM18xx-family register-reset reference, including revision 0x4e82a900; it does
not assert physical Nord reset or inherited loader inputs. Revision can remain
unknown and then fails on read. VSR starts unprogrammed even though its readable
reset value is zero: the manual explicitly requires programming it before use.

Implemented register behavior
101 pulse-latched source status/enables map through 32 channels onto two hosts.
Raw status survives masking. Enabled status is raw AND source enable. Channels
0/1 feed FIQ and 2..31 IRQ. Lowest channel wins, then lowest source index.
GER and HIER gate the host outputs separately from pending-index selection.
No input, interrupt acknowledgment, source clear or host sampling is implicit.

SISR/SICR and EISR/EICR set/clear indexed source status/enables. The four SRSR,
SECR, ESR and ECR words implement write-one set/clear behavior and readback;
only bits 0..4 exist in the last word. HIEISR/HIEICR and HIER control hosts.
CMR supports aligned byte, halfword and word accesses, including partial updates;
last-word unused lanes read zero. Other registers require aligned 32-bit access.

VBR/VSR calculate vector = base + source * (4 << size), explicitly wrapping
32 bits; no pending source returns VNR. GPIR/GPVR select across both hosts.
PRHOLDMODE freezes both host index and calculated vector when either is first
read, independently per host. Host index/vector writes, the documented indexed
host enable/disable operations and HIER written-one bits release that host's
hold. Disabling hold mode resumes dynamic readback. Pending sources are not
cleared by these release operations. Host outputs use live pending status.

Nesting protocol
CR NESTMODE 1/2 supports the documented per-host/global software override
protocol. GNLR/HINLR write bit 31 selects a persistent override, although readback
always clears that bit. The programmed nine-bit limit and hidden override flag
are separate state, both transactional. An override excludes equal and lower
priority channels from live selection/outputs; per-host overrides do not suppress
the other host. Mode 2 uses the global limit across both hosts. Modes 0/3 retain
the fields without applying these automatic-mode cutoffs; manual software can
mask individual sources/hosts.

Clearing OVERRIDE exposes the current eligible channel in the functional
reference; no eligible source reads 0x100. Firmware can read that value and
write it back with bit 31 set before acknowledging the source and re-enabling
ARM IRQs. The programmed values in AintcState remain distinct from this automatic
read view. Clearing a raw source does not erase an override. Held index/vector
pairs remain frozen until their documented release even if a threshold changes.

This is a software-visible interpretation of SPRUH82C 11.3.7/11.4.4/35/36,
corroborated by TI SYS/BIOS's documented HINLR-based IRQ dispatcher and FIQ
handler that does not use HINLR. It qualifies the tested override protocol,
not autonomous silicon update, held-priority/retrigger races or pin/bus-cycle
timing. Source pulses occur only at explicit host instruction boundaries in
tests. Arrivals in the clear/read/set window still need hardware qualification.
VSR >29, out-of-range source/channel indices, reserved writes, missing registers
and unsupported widths stop. No source synchronizer, debugger, reset sequencer
or physical peripheral event generation is modeled.

Memory integration
Memory::map_device binds one externally owned MemoryDevice to an explicit,
non-executable region. The device must outlive that Memory and be accessed only
on its owning emulation thread. RAM/device overlaps and repeated device mapping
in the same bus are rejected. read/write receive region-relative addresses;
faults include the original physical address, operation, width, PC and device.
peek observes RAM only and never triggers MMIO reads. Unknown holes are not RAM.

An instruction lazily joins each touched device's transaction before its first
read or write. Staged register read effects and writes are visible to subsequent
accesses in that instruction. Commit is non-throwing for devices; failure aborts
all joined devices and staged RAM writes. Memory destruction also aborts pending
effects; Memory cannot be copied/moved. Cache/MMU/buffer accesses still reach the
same physical bus, without an invented MMIO bypass or different CPU fetch path.
This is instruction rollback, not a qualified peripheral bus-cycle model.

Validation
Owned tests enumerate all 101 sources x 32 channels, check literal register/bit
expectations, priority ties, enable gates, masking retention, null/wrapping vectors,
independent holds/releases, channel lanes, malformed state/accesses and mixed
multi-device/RAM transactions. CPU LDM/STM tests fail on a second MMIO access
and check complete CPU/system/device rollback of the first read/write effect.

Optional original-image tests execute unchanged ARM0 FIQ/IRQ wrappers at
0xffff0060/0xffff008c in both images. Owned vector branches, source 40/41 pulses,
pointer table, four-instruction callback, counter, stacks and c1=0x52078 are
explicit fixtures; they are not source-wiring/reset claims. VSR is programmed.
CR=0x10 enables priority holding with automatic nesting disabled. Each wrapper
acknowledges its actual selected source via SICR, invokes the owned callback and
restores the original caller. Checks cover all caller registers/flags, IRQ/FIQ
stack frames, IRQ's System-mode callback frame, HINLR restoration, no held/raw
source left behind, unchanged ARM0 and normal caller resumption. The tests do
not qualify physical peripheral sources, boot or audio.
FIQ takes 11 original plus four owned callback instructions; IRQ takes 39 plus
four, excluding the exception-entry event and owned vector branch. Reproduce:

  build/strict/lead-a1-original-interrupt-test build/strict/share/ARM5_le.sla doc/local/images build/strict/generated/aintc-cases.bin

That test also composes original initialization with the nested dispatch in both
images. The unchanged vector installer, AINTC constructor, callback/channel
binding, source enables, nesting setter and global enable build the eight high
vectors, actual original-address table, CR=0x14 and IRQ override=100. The harness
supplies object/table RAM, stacks and calls under explicit c1=0x52078; it is not
the full board constructor/loader chain. A parent IRQ callback receives higher-
and equal-priority IRQ sources plus FIQ.
The original wrappers execute callbacks in FIQ/higher-IRQ/parent/equal order,
defer the equal source until the outer return, preserve both nested System/IRQ
frames and restore caller registers/flags, both stack banks and override 100.
Independent counter snapshots verify actual callback execution order. These are
owned callback/stack/event inputs, not proof of complete board initialization.

Original controller initialization
Private reconstruction 1660f7b identifies original constructor entries
0xc0172504 / 0xc002e258 and dispatch tables 0xc0767e6c / 0xc00a8004. The
optional original check executes both unchanged CODE images through 8 constructor
fixtures (four initial CR patterns each), plus 64 original helper calls. It
checks all eleven constructor MMIO stores in order, object/table publication,
VNR/VBR/VSR, the two CR updates selecting mode 1 then hold, unchanged GER/HIER,
indexed global enable/disable order, raw source operations, HINLR exchange and
the original unchecked channel argument spilling into its neighboring byte.
Caller saved registers/stack and all 428 original component bytes are preserved.

The constructor clears only bits 0..90 in ECR/SECR; the all-clear helper writes
three complete words. Tests deliberately retain bits 91..100 or 96..100 in the
101-source reference respectively. This is observed mask behavior, not evidence
that the exact Nord chip has 91, 96 or 101 sources. It does not reset channel
maps, GNLR/HINLR or all dispatch slots. The later board call supplies override
100, then enables hosts/global and finally ARM IRQ/FIQ; the full caller chain,
retained state and physical reset remain unqualified. Reproduce:

  build/strict/lead-a1-original-aintc-test build/strict/share/ARM5_le.sla doc/local/images
