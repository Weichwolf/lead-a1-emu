Native SHARC fixed-point integer arithmetic reference

Type2a now implements ADD, SUB, INC and DEC alongside the existing logical
operations. PGR rev2.4 table12-3 assigns opcodes1,2,0x29,0x2a; the native
COMPUTE field uses CU=ALU and its existing register/condition fields. All
primary/secondary bank selection, effective MODE1 latency and per-element
SIMD conditions use the same scalar reference as the logical operations.
No host SIMD/JIT/concurrency or instruction throughput is implied.

Arithmetic captures operands before writing the destination. INC/DEC do not
read Ry; unknown or differently banked unused Ry cannot affect execution.
Ordinary arithmetic requires known upper32 operand bits. SUB with identical
source registers establishes zero and no-borrow even when their value is
unknown. The low eight floating extension bits are ignored on input and set
to known zero on the result. Other unknown arithmetic inputs fail explicitly.

An unsigned64 adder computes the 32-bit result and carry without host signed
overflow or implicit narrowing. SUB/DEC use one's complement plus one; AC
therefore represents no-borrow. AV follows signed overflow independently of
carry. MODE1.ALUSAT (bit13) clamps overflow to the appropriate signed endpoint;
otherwise the result wraps. ALUSAT knowledge is needed only on overflow.
AZ/AN describe the actual output, including saturation. AV/AC describe the
arithmetic; AS/AI/AF clear. Other ASTAT bits, including CACC, are preserved.
Overflow sets AOS (STKY bit2) even with saturation enabled; subsequent ordinary
results preserve it. The other PE's flags and sticky state are independent.
Fixed COMP/COMPU flags and relational conditions have the separate
sharc-compare.txt contract. No arithmetic exception or data value is invented.

State, sticky flags, memory and pending control effects commit together.
Unknown PEy input after tentative PEx overflow rolls back both lanes, including
the tentative PEx AOS bit. Native one-instruction count loops execute each
arithmetic body normally. General loops, carry-input forms,
negation/ABS/MIN/MAX, other float (bounded add/sub is in
sharc-floating-point.txt), multiplier/multifunction and parallel
compute/moves remain outside this implemented subset and fail when encountered.
Separate LSHIFT/ASHIFT references are documented in sharc-shifts.txt.

Primary sources: pinned ADI Programming Reference rev2.4,11-1..3,11-11..12,
12-2..3,A-5,A-17..19,A-23. Manuals stay local; no original/reconstructed program
bytes or private encoder/decoder were imported. sharc_integer_arithmetic has
22 independent literal result/status cases in both saturation modes, including
both overflow directions, carry/no-borrow, dirty extension bits and preserved
CACC. It also checks all four SIMD condition outcomes, bank-half choices,
in-place operands, ignored Ry, saturation enable/disable latency, sticky/unknown
state, alias cancellation, rollback and a real three-iteration counter loop.

Original loader composition

The earlier genuine ARM/SPI header transfer still reaches171791 instructions
at word PC0x8c01b in all four kernel placements. Three original DEC operations
and their conditional branches now select tag3's code-record path at0x8c048.
The original Type5a I0=R3 and USTAT2=R2 transfers (sharc-register-moves.txt),
DEC R6=R2-1 and next conditional branch then reach word PC0x8c04c after171801
instructions. R0=0, I0 holds the received short-word destination, USTAT2 holds
the received count and R6=count-1. The last ALU status has AC=1,AZ/AV/AN=0.
The following immediate shift now executes, reaching171802/PC0x8c04d and the
unimplemented multi-instruction loop setup (sharc-shifts.txt). Its failure
preserves CPU/control/memory. The test has not loaded the application body or
completed the original uploader, cold boot or audio path.
