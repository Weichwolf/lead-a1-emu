ARM-state native reference execution

Native SLEIGH from pinned Ghidra 12.1.2 executes ARM5_le semantics. No JVM is
used. reference/ghidra.json pins the release and all consumed files. SLEIGH and
its static zlib dependency receive native sanitizers/hardening. Adapted public
executor infrastructure and the byte-memory patch are credited in THIRD_PARTY.txt.

Each step executes/commits one instruction. Decoder lookahead is side-effect-free;
executed bytes and guest cache-line fills must be known/executable. Decoding uses the
fetched instruction, including stale I-cache contents when configured. Without
an enabled I-cache, RAM code changes are visible on the next fetch.
Registers/temporaries are unknown until provided or
written. Caller-supplied CPSR flags synchronize individual flag storage. Explicit
RAM mappings distinguish unknown from loaded/written bytes. Access errors give
operation, address, width and PC. Failed instructions roll back register and
staged RAM writes. Images can initialize an offset within a larger RAM region;
surrounding bytes remain unknown. Peripheral side effects/interrupt delivery are
not implemented.

Host decode cache
At most 128 translations are retained, keyed by ARM PC and the fetched word.
Every instruction still performs the guest fetch and executes its p-code with
current registers, flags and memory. This cache does not replace the guest
instruction cache or elide loop iterations. A miss creates a fresh ARM5 decoder
context; decompiler flow hints are not architectural state. This also avoids
re-registering variables in an initialized SLEIGH context after MOV LR,PC.
ARM/Thumb switching remains unsupported. ArmExecutionOptions can disable the
host cache for comparison; decode_statistics reports host work, not guest state.
Host translation statistics are excluded from instruction rollback.

Owned tests compare cached/uncached state, assembly and data after each of 256
instructions, including changed/restored opcodes. Independent final arithmetic
expectations supplement equivalence. Identical PC-relative opcodes at 129
different addresses test address keys and cache bounds. MOV LR,PC followed by
BX and LDR PC checks indirect calls/returns, LR and unchanged flags in both paths.

Evidence
- Owned assembly tests: overflow/comparison flags, conditions, little-endian
  loads/stores, PC/branches, even BX, RAM mutation, isolated final instruction.
- Odd BX is rejected before commit because Thumb is pending. Unknown operands
  and partial LDM/STM failures preserve prior registers/RAM.
- Both unchanged original ARM0 entries execute two instructions and transfer to
  CODE. The fixture supplies only PC and CPSR 0xd3; other registers start unknown.
  All six decoded section SHA-256 identities are checked before execution.

Status and bank adapter
MRS/MSR execute through an owned ARMv5 architecture adapter. Current status
reads include mode/interrupt bits; immediate and register writes synchronize
N/Z/C/V/Q with native arithmetic and honor selected fields and privilege.
All seven supported processor modes are validated. FIQ has separate r8-r12;
User and System share SP/LR, while FIQ/IRQ/Supervisor/Abort/Undefined have their
own SP/LR and SPSR. Unknown inactive registers remain unknown. ArmState banks
are canonical snapshots; supplied active registers take precedence over duplicate
active-bank fields at initialization. Partial SPSR writes retain bit knowledge;
reading uninitialized implemented bits fails. Reserved status bits are modeled
as zero and attempts to set them are rejected as unpredictable. Unsupported
execution-state changes, invalid modes, PC status operands/destinations, exception
returns and user-bank block transfers stop without committing side effects.
Independent expectations follow the ARM references in arm-architecture.json.

Owned assembly covers every bank, User/System aliasing and privilege, immediate
rotations, Q flag set/clear, masked/conditional writes, incomplete saved state
and invalid forms. Literal truth masks check all 15 ARM conditions over all 16
N/Z/C/V combinations. Native ADC observes MSR-written carry. Complete state
comparisons include bank contents on failures; conditional failures do not read
unknown operands.

Bounded ARM926 system reference
This flat-memory profile assumes disabled MMU and TCM regions.
An optional explicit system profile adds CP15 control c1 and whole I/D-cache
invalidation plus write-buffer drain through c7. The ARM926 TRM is pinned in
arm-architecture.json. Control SBO bits are 0x00050078; V and B depend on reset
inputs and the actual software-entry state is not established. No profile means
executed CP15 access fails, preserving the earlier flat instruction reference.
Unknown supplied control, cache validity/geometry or write-buffer contents fail
when needed. Conditional CP15 operations do not inspect untaken operands.

Enabled instruction fetch uses 32-byte, four-way cache lines. Guest data writes
leave cached instructions intact; invalidation discards them. Disabling I-cache
bypasses it without discarding lines. MMU-disabled data accesses bypass D-cache
regardless of C, as documented by the TRM. Supplied pending buffer writes drain
through the real memory transaction; partial failures roll back CPU, RAM and
system state. Cache fills/invalidation/counters also commit only on success.
The profile deliberately supplies cache size; it does not fabricate a CPU/cache
ID. Replacing a valid line stops until random/round-robin internal replacement
state is qualified. MMU, TCM, big endian, legacy PC loads, WFI and other CP15
operations remain unsupported. Exception delivery and cycle timing are pending.

Owned assembly verifies stale instructions, Harvard data visibility, invalidation,
disable/re-enable retention, control masks/privilege, NZCV reads to PC, unknown
fetch inputs, incomplete lines, conditional skips and transactional buffer faults.
Conflicting cache sets fail unchanged rather than using invented replacement
state. These are bounded reference semantics, not hardware cache qualification.

Current original checkpoint
Without a system profile, both originals stop unchanged at CODE +0x10 with a
complete CP15 diagnostic. With explicit reference inputs (control 0x00050078,
16 KiB instruction cache, initially unresolved cache validity and known-empty
write buffer), both unchanged ARM0/CODE paths reach CODE +0x158 after 46 guest
instructions. Original invalidation resolves cache validity before enabling it.
All six banked stack tops and System mode with IRQ/FIQ masked match independent
private reconstruction expectations. With only PC/CPSR initially supplied, the
initializer's first PUSH stops unchanged on unknown preserved registers.

The extended fixture supplies explicit nonzero caller markers in r3/r7/r9/r10/
r11, 16 MiB DDR, 128 KiB shared RAM and 8 KiB local RAM, placing ARM0 at offset
0x20. Region extents follow observed original mapping-constructor arguments,
not physical reset qualification. Only sections plus the BSS/tail test fill are
loaded; other RAM remains unknown. The original initializer clears its own BSS
from a 0xa5 test fill and reaches CODE +0x298 before runtime continuation:

Part   Instructions   BSS bytes   BSS start      BSS end (exclusive)
0      2335493        0x474578    0xc0300550     0xc0774ac8
1      63861          0x01f258    0xc008a438     0xc00a9690

Every decoded CODE byte remains unchanged; all BSS bytes are known zero and
the next 16 bytes retain 0xa5. The System stack frame contains the three caller
markers and exact original return address. Region count, preserved r9/r10,
SP and CPSR flags/masks are checked. No guest loop is replaced by host clearing.

This is software-entry execution, not physical reset, ROM loading, hardware cache
qualification, DSP loading, audio or MIDI. Original instructions/disassembly and
private reconstruction sources are not embedded in public tests.

Original checks skip explicitly without local firmware. Owned instruction/RAM
tests remain mandatory. Native checks audit actual compile commands, all three
dependency archives' sanitizer hooks and executable PIE/RELRO/NX properties.
With verified extracted images, an optional bounded continuation probe writes
its raw trace only to ignored local storage (part 0 is the longer BSS test):

  build/strict/lead-a1-original-arm-test build/strict/share/ARM5_le.sla doc/local/images 1 --probe-runtime >doc/local/arm-runtime.log 2>&1

The probe stops visibly on an unsupported operation or its instruction budget;
it is diagnostic evidence, not an additional boot acceptance result.
