ARM-state native reference execution

Native SLEIGH from pinned Ghidra 12.1.2 executes ARM5_le semantics. No JVM is
used. reference/ghidra.json pins the release and all consumed files. SLEIGH and
its static zlib dependency receive native sanitizers/hardening. Adapted public
executor infrastructure and the byte-memory patch are credited in THIRD_PARTY.txt.

Each step executes/commits one instruction. Decoder lookahead is side-effect-free;
executed bytes and guest cache-line fills must be known/executable. Decoding uses the
fetched instruction, including stale I-cache contents when configured. Without
an enabled I-cache, RAM code changes are visible on the next fetch.
Registers/temporaries are unknown until provided or
written. Caller-supplied CPSR flags synchronize individual flag storage. Explicit
RAM mappings distinguish unknown from loaded/written bytes. Access errors give
operation, address, width and PC. Failed instructions roll back register and
staged RAM writes. Images can initialize an offset within a larger RAM region;
surrounding bytes remain unknown. Explicit MMIO mappings stage device read/write
effects in the same instruction transaction (aintc.txt). Functional ARM-state
exception delivery and return are described in arm-exceptions.txt; board IRQ
sources remain pending.

Host decode cache
At most 128 translations are retained, keyed by ARM PC and the fetched word.
Every instruction still performs the guest fetch and executes its p-code with
current registers, flags and memory. This cache does not replace the guest
instruction cache or elide loop iterations. A miss creates a fresh ARM5 decoder
context; decompiler flow hints are not architectural state. This also avoids
re-registering variables in an initialized SLEIGH context after MOV LR,PC.
ARM/Thumb switching remains unsupported. ArmExecutionOptions can disable the
host cache for comparison; decode_statistics reports host work, not guest state.
Host translation statistics are excluded from instruction rollback.

Owned tests compare cached/uncached state, assembly and data after each of 256
instructions, including changed/restored opcodes. Independent final arithmetic
expectations supplement equivalence. Identical PC-relative opcodes at 129
different addresses test address keys and cache bounds. MOV LR,PC followed by
BX and LDR PC checks indirect calls/returns, LR and unchanged flags in both paths.

Evidence
- Owned assembly tests: overflow/comparison flags, conditions, little-endian
  loads/stores, PC/branches, even BX, RAM mutation, isolated final instruction.
- Odd BX is rejected before commit because Thumb is pending. Unknown operands
  and partial LDM/STM failures preserve prior registers/RAM.
- Both unchanged original ARM0 entries execute two instructions and transfer to
  CODE. The fixture supplies only PC and CPSR 0xd3; other registers start unknown.
  All six decoded section SHA-256 identities are checked before execution.

Status and bank adapter
MRS/MSR execute through an owned ARMv5 architecture adapter. Current status
reads include mode/interrupt bits; immediate and register writes synchronize
N/Z/C/V/Q with native arithmetic and honor selected fields and privilege.
All seven supported processor modes are validated. FIQ has separate r8-r12;
User and System share SP/LR, while FIQ/IRQ/Supervisor/Abort/Undefined have their
own SP/LR and SPSR. Unknown inactive registers remain unknown. ArmState banks
are canonical snapshots; supplied active registers take precedence over duplicate
active-bank fields at initialization. Partial SPSR writes retain bit knowledge;
reading uninitialized implemented bits fails. Reserved status bits are modeled
as zero and attempts to set them are rejected as unpredictable. Unsupported
execution-state changes, invalid modes, PC status operands/destinations and
user-bank block transfers without PC stop without committing side effects.
ARM exception-return forms use the separate adapter in arm-exceptions.txt.
Independent expectations follow the ARM references in arm-architecture.json.

The adapter also handles canonical NOP and MOV LR,PC. The latter copies PC+8
with 32-bit wrap, advances PC by four and preserves flags; an untaken condition
preserves unknown LR. This avoids SLEIGH's special MOV LR,PC constructor reading
an unused shift-carry temporary before any earlier instruction initialized it.
Owned tests start directly on the instruction across all NZCV combinations and
at the address-space end. Unrelated registers remain unknown.

Owned assembly covers every bank, User/System aliasing and privilege, immediate
rotations, Q flag set/clear, masked/conditional writes, incomplete saved state
and invalid forms. Literal truth masks check all 15 ARM conditions over all 16
N/Z/C/V combinations. Native ADC observes MSR-written carry. Complete state
comparisons include bank contents on failures; conditional failures do not read
unknown operands.

Bounded ARM926 system reference
TCM regions remain disabled in this reference.
An optional explicit system profile adds CP15 control c1, I/D cache-lockdown
registers c9, whole I/D-cache invalidation and write-buffer drain through c7,
plus the bounded MMU reference below.
The ARM926 TRM is pinned in
arm-architecture.json. Control SBO bits are 0x00050078; V and B depend on reset
inputs and the actual software-entry state is not established. No profile means
executed CP15 access fails, preserving the earlier flat instruction reference.
Unknown supplied control, cache validity/geometry/lockdown or write-buffer contents fail
when needed. Conditional CP15 operations do not inspect untaken operands.

Enabled instruction fetch uses 32-byte, four-way cache lines. Guest data writes
leave cached instructions intact; invalidation discards them. Disabling I-cache
bypasses it without discarding lines. MMU-disabled data accesses bypass D-cache
regardless of C, as documented by the TRM. Supplied pending buffer writes drain
through the real memory transaction; partial failures roll back CPU, RAM and
system state. Cache fills/invalidation/counters also commit only on success.
The profile deliberately supplies cache size; it does not fabricate a CPU/cache
ID. Each c9 L bit prevents allocation into its way, preserving hits on existing
lines. Writes do not invalidate lines. If exactly one way is available, linefills
and eviction are deterministic; all four L bits set selects way 3 as documented.
With multiple available ways, replacing a valid line still stops until random/
round-robin internal replacement state is qualified. The functional D-cache and
RAM-bus reference is described in arm-data.txt. TCM, big endian,
legacy PC loads, WFI and other CP15
operations remain unsupported. Automatic fault delivery and cycle timing remain
pending.

Owned assembly verifies stale instructions, Harvard data visibility, invalidation,
disable/re-enable retention, control masks/privilege, NZCV reads to PC, unknown
fetch inputs, incomplete lines, conditional skips and transactional buffer faults.
All sixteen lockdown masks are tested. Separate I/D read-modify-write, unknown
inputs, SBO/reserved fields, protected stale lines, deterministic eviction and
the all-locked fallback have independent expectations. Conflicting sets with
multiple eligible ways fail unchanged. These are bounded reference semantics,
not hardware cache qualification.

I-cache single-line invalidation accepts MVA and Set/Way c7 forms, including
when I-cache is disabled. It checks word/SBZ/index bits and uses already modified
addresses without translation/PID adjustment. A two-entry instruction journal
commits a new fetch line together with invalidation of another line; invalidating
the just-fetched line discards that fill. Misses do not fetch the operand address.
Whole invalidation still discards every line. Instruction linefill requests start
at the critical word and wrap; full known-line commit has no early restart/timing
claim. Owned programs cover stale opcodes, current/new/other lines, nonzero sets,
unknown/invalid inputs, conditional skips and rollback. Prefetch is pending.

MMU reference
ArmMmuInitial supplies known or explicitly unknown TTBR, domain access, FCSE PID,
context ID, TLB-lockdown register and validity of normal/locked TLB contents.
There are no guessed translation defaults. CP15 c2/c3/c8/c10/c13 support table,
domain, unified-TLB maintenance/lockdown and FCSE/context registers. Low TTBR,
PID and lockdown reserved bits are checked. Context ID is a trace value, not an
ASID. Invalidate-all clears ordinary entries, preserving locked entries;
single-MVA invalidation includes locked entries and takes an already modified
address, without adding the current PID again.

With M=1 and C=0, instruction/data accesses walk section, coarse and fine tables
through physical memory. Large/small/tiny pages, heterogeneous AP subpages,
domain modes, AP/S/R privilege and FCSE low-address translation have independent
expectations. TLB entries retain mappings across table edits and TTBR writes
until explicit invalidation. Eight locked entries use the documented victim
increment/wrap. Normal entries use a bounded 64-entry retention reference; a full
reference TLB stops on unqualified replacement. This is not a qualification of
the silicon's two-way TLB indexing/replacement or speculative table walks.

Instruction-cache tags use modified virtual addresses; fills use translated
physical addresses. Translation and access permissions are checked even on hits.
Noncacheable instructions bypass the cache. Data accesses use the functional
cache/buffer reference in arm-data.txt, including physical table-read coherence
with buffered stores. Initial buffer contents must be explicit; pending stores
are not silently forwarded or discarded. Control transitions require unchanged physical
addresses for the two following instruction words and unchanged cache tag/
cacheability when I-cache is enabled. Combined MMU/I-cache toggles and active
FCSE PID changes are guarded pending a qualified prefetch model.

Translation/domain/permission/alignment faults are diagnostics with operation,
VA, MVA, status and domain where defined. CPU/RAM/MMU state rolls back on a
failed instruction, including partial LDM/STM. Abort exception delivery and
c5/c6 fault-register latching are pending. IRQ/FIQ/SWI delivery does not convert
these diagnostic MMU faults into exceptions yet. Unknown physical table bytes
remain explicit memory failures; they are not fabricated external-abort responses.
Owned CPU tests cover guest register setup, identity MMU enabling, translated
loads/stores, TLB remapping, stale virtual instruction tags, user/LDRT/STRT
permissions and transactional faults. A canonical ARMv5 NOP preserves unknown
r0 without reading it. Literal page-address and AP/S/R/domain matrices complement
CPU integration; no original instruction bytes are embedded in these tests.

Current original checkpoint
Without a system profile, both originals stop unchanged at CODE +0x10 with a
complete CP15 diagnostic. With explicit reference inputs (control 0x00050078,
16 KiB instruction cache, c9 I/D=0xfff0 (all ways available), initially unresolved
cache validity and known-empty
write buffer), both unchanged ARM0/CODE paths reach CODE +0x158 after 46 guest
instructions. Original invalidation resolves cache validity before enabling it.
All six banked stack tops and System mode with IRQ/FIQ masked match independent
private reconstruction expectations. With only PC/CPSR initially supplied, the
initializer's first PUSH stops unchanged on unknown preserved registers.

The extended fixture supplies explicit nonzero caller markers in r3/r7/r9/r10/
r11, 16 MiB DDR, 128 KiB shared RAM and 8 KiB local RAM, placing ARM0 at offset
0x20. Region extents follow observed original mapping-constructor arguments,
not physical reset qualification. Only sections plus the BSS/tail test fill are
loaded; other RAM remains unknown. The original initializer clears its own BSS
from a 0xa5 test fill and reaches CODE +0x298 before runtime continuation:

Every decoded CODE byte remains unchanged; all BSS bytes are known zero and
the next 16 bytes retain 0xa5. The System stack frame contains the three caller
markers and exact original return address. Region count, preserved r9/r10,
SP and CPSR flags/masks are checked. No guest loop is replaced by host clearing.

This is software-entry execution, not physical reset, ROM loading, hardware cache
qualification, DSP loading, audio or MIDI. Original instructions/disassembly and
private reconstruction sources are not embedded in public tests.

Original checks skip explicitly without local firmware. Owned instruction/RAM
tests remain mandatory. Native checks audit actual compile commands, all three
dependency archives' sanitizer hooks and executable PIE/RELRO/NX properties.
With verified extracted images, an optional bounded continuation probe writes
its raw trace only to ignored local storage (part 0 is the longer BSS test):

  build/strict/lead-a1-original-arm-test build/strict/share/ARM5_le.sla doc/local/images 1 --probe-runtime 250000 >doc/local/arm-runtime.log 2>&1

The optional numeric budget is 1..3000000; default 4096. A stop reports committed
steps, registers and CPSR. With all ways available, part 1 stops after 42838
additional steps at 0xc005b24c on unresolved random cache replacement.

An additional --single-cache-way argument supplies entry I-lockdown=0xfffe,
restricting allocation to way 0. This is a documented ARM926 mode selected as a
separate software-entry experiment; it does not establish the physical loader's
cache state. It retains the same firmware, RAM sizes, c1 and caller inputs.
This fixture also supplies a 16 KiB D-cache, known-empty write-back buffer,
FCSE PID=0, TLB lockdown=0 and known-invalid locked
TLB entries. Initial TTBR/domain access/context ID and normal TLB contents are
unknown. Part 1 reaches the c1 write at 0xc002e16c after 88530 additional steps,
r0=0x5107f. It stops unchanged on unknown ordinary TLB contents during MMU
transition qualification, after original TTBR/domain writes,
cache invalidation and buffer drain. There is no TLB invalidation on this enable
path, so ordinary TLB contents remain unresolved. The inherited c1.V stays zero
in this fixture; installing high vectors does not select them.
All eight guest-generated high vectors match the independently
reconstructed ARM0 handler targets. Raw disassembly/traces stay ignored locally.

Independent reconstruction also identifies a descriptor discrepancy: the original
L1 section/coarse/fine words leave bit 4 clear; ARM DDI 0198E requires it set.
The reference rejects that encoding. Exact silicon/SoC acceptance remains
unqualified; do not repair guest table words or silently accept them to advance.
The three original RAM mappings select C/B=3 under domain 0 Manager, whose
permissions bypass AP; unrelated L1 entries remain identity sections. These
findings do not supply an initial TLB or qualify D-cache/prefetch behavior.
At this stop the optional probe checks every directory/coarse-pool/fine-pool
word against independent reconstruction expressions, preserving these quirks.

The probe stops visibly on an unsupported operation or its instruction budget.
Its checkpoints do not establish physical reset, complete boot or device equivalence.
