SHARC programmable SPI receive DMA reference

SharcSpi is the runtime continuation of the explicit 214xx slave-bootstrap
reference, not another hardcoded block loader. Its constructor requires a
completed 384-word SharcSpiBoot state. Selection, clock baseline and word
alignment survive the handoff; SPICTL remains 0x4d22 (slave, LSB32, idle high,
rising sample, DMISO, TIMOD DMA, GM discard). No physical wiring, latency,
clock rate, historical core interrupt state or ready signal is implied.

Map IOP words0x1080..0x1084 to this device. IMSPI supplies a signed16 modifier;
IISPI selects a normal-word internal address with offset0x80000 and a wrapped
19-bit cursor. CSPI writes arm a transfer; writing zero requests65536 words,
while a completed count of zero remains idle until another software write.
The initial runtime count is the completed bootstrap count, not a new write.
The modifier/index may change after completion before the next count write.
Active parameter changes fail until separately qualified.

There are four DMA FIFO words and one receive buffer. Serial rising edges
shift actual MOSI, and a complete word enters the receive path. Enabled DMA
moves the receive buffer into available FIFO space even after count reaches
zero, preserving received-ahead data for later DMA blocks. If both FIFO and
receive buffer are full, another complete word raises receive overflow and
is discarded (GM=0). There is no unlimited queue. DMA disabling preserves
the FIFO; the SPI port remains enabled and can fill its receive buffer.

A DMA request needs min(4,remaining) FIFO words. A separate explicit owner
grant services one whole group transactionally through SharcMemory, using
32-bit normal-word writes independently of SYSCTL core data widths. A failed
write anywhere in the group rolls back memory, count, cursor, FIFO and IRQ.
Neither status reads nor incomplete wire words grant memory access. Core
instructions and external serial/grant events cannot overlap transactions.
This functional grant API does not yet establish IOP arbitration/retirement
timing or simultaneous core/DMA bus priorities.

SPIDMAC supports enable, receive, completion-IRQ enable and error-IRQ enable.
Its reads expose actual count-derived busy, FIFO empty/partial/full and
overflow/error state. Transmit, chaining, external-completion selection, FIFO
flush and unimplemented/reserved writes fail. SPICTL/SPISTAT/RXSPI and other
register blocks are not mapped by this DMA-only facade: unknown reads and
error-clear/flush requests must not silently succeed.

IISPI raw readback remains explicitly guarded. HWR3-4's bit-width/offset
prose is inconsistent with the 19-bit table and3-28's wrap description; the
functional address path follows the latter. The boot table's full logical
destination does not establish whether the offset bit is forced on readback.
Do not infer a physical register value from the diagnostic logical cursor.
ADI employee Mahesh's July8,2014 reply also describes low19 plus0x80000 for
buffer writes. Its numerical example has an arithmetic typo (low19 of0xb2000
is0x32000); neither that example nor the post specifies CPU raw readback:
https://ez.analog.com/dsp/sharc-processors/f/q-a/61465/21489-spi-dma

Completion with INTEN, or receive overflow with INTERR, records a peripheral
interrupt event. The board owner must route it to the processor before
acknowledging it. Enabling INTERR with an existing overflow also requests an
interrupt. Sharc::latch_interrupt explicitly latches maskable IRPTL bits
even if IMASK or MODE1.IRPTEN disables delivery; pending software latch effects
retain a newly arriving event. This is separate from the peripheral event
acknowledgement. Enabled interrupt entry/RTI and secondary LIRPTL remain open
and fail at the existing execution guard. Held error-line reassertion requires
the future SPISTAT/interrupt-service model. The primary default route is P1I,
IRPTL bit12, not an implicit assignment of a Nord transport to a package.

Primary sources: ADI ADSP-214xx HWR rev1.1,3-5..7,3-28,16-20..22,16-26..32,
A-228..232,B-12; Programming Reference rev2.4,A-39..40 (IRPTL bit12).
Pinned provenance is in reference/sharc.json; manuals stay ignored/local.
Owned sharc_runtime_spi checks independent literal data/framing, finite FIFO
capacity, four-word/final-short requests, retained data, signed stepping,
zero count, interrupt enable/masking, failed-grant rollback, MMIO abort and
unsupported/unknown inputs. It also clocks all65536 words for a zero-count
request and checks both cursor-wrap directions using owned endpoint cells.

Original serial/core composition

The optional original SPI test retains its separate unmapped-IOP rollback at
PC0x8c034, then maps this runtime device. Seven original instructions program
IMSPI=1,IISPI=0x92003,CSPI=3 and complete a busy-poll iteration. The genuine
ARM block writer sends the next twelve bytes from each unchanged stream over
the existing TI SPI model. All six halfwords and all three RAM header words
are checked against the original read-only storage. Exactly one three-word
DMA grant commits; busy then clears and the completion event routes explicitly
to default primary P1I. IMASK3 preserves that latch without delivering it.

Ten further original instructions poll, read the received header, return,
load its count/destination and begin tag dispatch. All four placements reach
word PC0x8c01b after171791 committed instructions, with depth0 and original
tag/count/destination in R0/R8,R2,R3. Native integer arithmetic and UREG
transfers then continue the composition through171801 instructions
to PC0x8c04c (sharc-arithmetic.txt). Native immediate LSHIFT then reaches
171802/PC0x8c04d (sharc-shifts.txt). The long count loop and actual next one-word
ARM transfer then reach171817/PC0x8c04f after genuine polling/read/RTS, with
the loop count unchanged by its callee (sharc-long-loops.txt). Actual short-word
and Type3a stores then complete the first code record and receive/dispatch
the next header (sharc-ram-moves.txt). Earlier preservation
oracle precedes the genuine runtime writes at0x92003..5, which legitimately
alias old NOP instruction storage.

This fixture deliberately pauses DSP execution during the ARM header call
and grants requested DMA between serial edges/ARM instructions. It is an
explicit functional reference, not a complete original-uploader execution or
qualified physical bus schedule. Both actual uploader entries segment each
stream at384 words and poll GPIO bank3 inputs before sending the remainder;
their complete concurrent handshake, physical FLAG/pad wiring and timing are
still open. No host memcpy, firmware patch or fake ready response is used.
Complete boot, application audio and hardware equivalence remain separate
acceptance requirements.
