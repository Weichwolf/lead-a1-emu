SHARC finalizer evidence and remaining execution boundary

The bound original setup now reaches CPU8c08e with its actual Address-stage
DB target selected, PM request/cache handling and deferred type0 frame
intact (sharc-fetch-finalizer.txt). The later arithmetic continuation executes
entry DB/IDLE, receives all384 vector words, accepts P1I and retires the actual
temporary RTI through restored8c003 (sharc-loop-idle.txt). The
foreground continuation retires its real NOP and self-modifying PM/SYSCTL
store, then preserves the next quiet SYSCTL width failure
(sharc-arithmetic-cache.txt). A separate explicit candidate late-response
profile executes the rewritten word, restores the saved vector and reaches
8c005 (sharc-fetch-memory.txt); its physical response phase is unqualified.
The next original JUMP selects VISA. Its separate input-buffer check and
still-guarded native transport boundary are in sharc-visa.txt. No VISA
instruction in that clocked path, application startup or complete boot is
qualified. A separate CPU instruction-order fork executes the actual first
VISA clock call and returns (sharc-visa-execution.txt); it does not resolve
the native/VISA clocked connection or physical memory-response phase.

The qualified PX/bit/parallel prefix is documented separately. Arithmetic DO
and deferred PC-stack setup have a bounded reference in sharc-arithmetic-loops.txt.
The pure cache invalidation and Type1 dual-memory instruction references are
in sharc-cache.txt/sharc-dual-moves.txt. Unlooped P1I/RTI and ordinary IDLE
have separate contracts in sharc-interrupts.txt/sharc-idle.txt. The further
unlooped fetched DB/IDLE, retained slot and P1I/RTI redirect component is in
sharc-delayed-idle.txt. The arithmetic-entry composition in sharc-loop-idle.txt
extends the native frame/retained slot/DMA/P1I/RTI path. Self-modifying stores,
general interrupted-loop execution and the combined cache/prefetch path
remain unqualified; application boot does not follow from these components.
The separate instruction-bus transport in sharc-fetch.txt captures actual F2
data and retires retained words through the native core. Its bound cache clock
has the explicit-input contract in sharc-fetch-cache.txt. Its optional cursor
and JUMP/CALL/RTS redirects are in sharc-fetch-flow.txt, with Address-stage
decisions/interlocks in sharc-branch-pipeline.txt. These do not yet
supply the original finalizer's complete cache/redirect/loop/IDLE pipeline.

Primary-reference provenance is recorded in reference/sharc.json:
- PGRrev2.4,4-53/54: arithmetic-loop termination tests when the second body
  instruction is fetched;4-58 describes short-loop draining. The counter-loop
  e-4 rule must not be reused as the arithmetic-loop rule.
- PGR A-11 keeps a loop type in LADDR separately from the PC-stack start.
  A later PCSTK write must not silently reclassify a loop by its new length.
- PGR A-10 sets PCSTK bit25 on interrupt pushes with CALL bit24 clear.
  PGR4-28/35 holds the active source latch clear;4-40/41 applies automatic
  status/MMASK changes to IRQx/timer, not P1I. These constrain the separate
  ordinary reference without qualifying the finalizer's loop/branch entry.
- PGR A-32 counts effect latency in processor clocks and explicitly includes
  interrupt breaks. The ordinary reference settles pending core/SYSCTL effects
  during accepted internal entry; a first-handler bank/width regression rejects
  the old instruction-only pending-effect interpretation.
- sharc-quiet-clocks.txt separately qualifies selected core/SYSCTL effects with
  no Execute instruction. Mode/width/flush interlocks remain guarded; the
  separate setup qualification is in sharc-fetch-finalizer.txt; neither
  component qualifies final vector/reentry execution or complete boot.
- PGR4-22/23 delays interrupt service across a delayed branch and describes
  an IDLE-in-delay-slot deadlock. HWRrev1.1,24-25..27 explicitly describes
  the final vector DMA with delayed branch and IDLE instead.
- CCES2.9rev2.3,10-16..19 documents saved-header instruction packing and
  vector restoration. Its finalization explanation separates IDLE completion,
  branch completion/mask clear, interrupt entry and RTI. The illustrated
  ADSP-2126x listing does not qualify ADSP-21489 pipeline details or counts.
- KRZ/Klaus's24 April2015 manufacturer-hosted ADSP-21489 discussion posts
  a boot-kernel explanation corroborating wake before delayed service,
  the retained mask slot and RTI to the completed branch target. This is
  source-level corroboration, not a measured physical pipeline trace.
- The official VisualDSP++5.1.2 package's ADSP-21489 SPI kernel independently
  supplies the same ordering and self-modifying-loop explanation. The source
  file stays local; reference/visualdsp.json pins its size/hash. Presence or
  inspection of this file does not qualify simulator or physical execution.
- The official2148x anomaly list NR004008L distinguishes IRQx/timer status
  returns (15000002), external-data control latency (15000004) and VISA
  internal-write visibility (15000024). Its IDLE case15000021 concerns a
  debugger/core-timer sequence; no FINAL_INIT wake exception is established.
  Physical silicon revision and applicability remain unknown. The document
  was reviewed online; reference/sharc.json does not claim a local byte hash.

The hardware-specific boot evidence now constrains the bounded unlooped
component in sharc-delayed-idle.txt. Original loop/cache/drain composition
and physical timing remain to qualify. Do not replace IDLE by NOP,
copy vectors through the host, patch a branch or summarize the self-modifying
loop. Wake, interrupt acceptance/service, pending control latency, fetched
instruction visibility and loop-stack effects require independent tests.
The original final header's saved instruction and vector addresses are factual
input metadata; the hypothesized number of loop passes is not qualified timing.
