Explicit MCU GPIO / SHARC FLAG connections

ProcessorLinks joins caller-supplied logical GPIO-bank/pin and DSP-slot/FLAG
endpoints. There is no built-in Nord pinout, processor count, pull resistor,
pinmux, synchronizer delay or instruction-frequency ratio. The caller owns
the devices and supplies established sampling boundaries on one emulation
thread. Physical routing and timing remain unqualified.

Each point-to-point wire resolves committed GPIO output-enable/latch state,
effective SHARC FLAG direction/latch state and an explicit external driver.
An unopposed known real drive determines the level. Unresolved or conflicting
real drives stay unknown. Only when all real drivers are HiZ can the explicit
ProcessorWire.pull supply a weak HIGH/LOW; its default is absent. No missing
physical input is guessed. external() drivers have equal strong logical
strength and remain distinct from this weak topology input.
Per-driver HIGH/LOW/unresolved masks remain available in the last sampled
resolution; a weak level sets none of those strong-driver masks. Topology
snapshots retain the optional pull and validate sampled resolutions against it.
Unsampled snapshots retain absent levels until sample(). Every endpoint must be
unique; unsupported fanout/multiple-net configurations reject instead of silently
dropping a connection.

sample() checks every device's instruction ownership and validates every
proposed sample before changing any input, edge status or published resolution.
The existing unknown GPIO edge-baseline/new-level guard remains in force.
No callback, allocation or guest execution occurs during publication. A failure
preserves all devices and the last published link state; retry needs no fake
guest instruction. Unconnected input bits retain their owner-supplied knowledge.

external() stages a driver; it publishes nothing until sample(). snapshot()
records the immutable topology, staged external drives and most recent sampled
levels, not a claim that those old levels track later unsampled guest writes.
Independent restoration requires matching GPIO/core/memory snapshots as well.
Reserved drive tags and inconsistent resolution/topology snapshots reject.
Gpio::check_sample and Sharc::check_flag_inputs expose the same side-effect-free
validation used by their ordinary sample methods; no alternative write path
bypasses the guards.

Owned tests enumerate all 48 GPIO/DSP/external drive combinations with absent,
LOW and HIGH pulls: 144 cases against an independent resolution table. Actual
FLAG direction/SET/CLR instructions additionally check HiZ -> unresolved output
-> HIGH -> LOW -> HiZ, including effect latency and restored weak/strong states.
They retain known-low versus unknown, conflicting drivers, unconnected samples, multiple participants, malformed snapshots and
foreign-instruction rollback. Independent restores retain pending IRQ bits;
after actual W1C acknowledgement, unchanged HIGH samples do not relatch them.
An assembled owned ARM program preloads a GPIO
latch, enables its driver, reads the actual readiness input and asserts release.
Real SHARC FLAGS direction/SET/CLR/TST and following NOPs provide status and
consume release. Missing readiness reads reject; repaired reads consume the
actual resolved value. This tests logical coupling, not physical Nord timing.

Original uploader reference

Unmodified OS 1.36 CODE has uploader entries c01348b8/c00051cc and first
readiness LDRH PCs c0134948/c000525c. Private factual handoff6401062330 and
our independent hash-checked original-field inspection agree on bank 3:
CLEAR4 then1; inputs3/1, outputs2/0; transport1 kernel before status-mask 8.
The register identities are DIR 01e2603a,SET 01e26042,CLEAR 01e26046,INPUT 01e2604a.
These are software identities, not measured package pins. Raw FLAGS mask 4 is
core FLG1's level in the PGR reference, not automatically a physical "FLAG2".

The optional uploader cases execute real allocation/GPIO/SPI calls and all 768
kernel halfwords before the first unknown readiness read. The failed original
LDRH preserves ARM/GPIO/SPI state and consumes no manufactured reply. The same
received kernel executes its clock setup and 171758-instruction readiness prefix,
including all original RAM-clear oracles. A named software-wiring candidate
connects bank 3 pin2 to that transport's core FLAG0 and pin3 to core FLAG1.
The source is the kernel's actual known HIGH output; the original MCU then
executes its real LDRH/TST/BEQ and reaches the first remainder-send setup.
The serial pin path uses SpiSharcLink (spi-sharc-link.txt); functional clock
cadence, DMA grants and the MISO pull remain explicit fixture inputs. The
shared SPI bus needed for multiple receivers is qualified separately in
spi-sharc-bus.txt; it does not itself advance this first-handshake reference.

Paired-input reference (original_arm_spi_uploader_pulls_0/1)
The same actual first kernel and readiness prefix also run with a second,
unexecuted core-input reference attached to bank3 pins0/1. Its FLAG directions
are inputs; no initial boot transition/frame or second kernel execution is
supplied. Its software-entry PC is bookkeeping, not a qualified reset PC. Only
unconnected pads4..15 have explicit owned samples (maskfff0). Both actual
release and readiness wires are resolved from their drivers.

Without a pull, the other readiness pad remains unknown (maskfffd) and the
original MCU LDRH still rejects, preserving all state. Explicit owned LOW pulls
on readiness wires then supply only the idle HiZ level. The running kernel's
actual HIGH overrides its LOW pull; strong-driver masks identify that source.
The same original LDRH/TST/BEQ reaches the first remainder-send setup. The idle
core changes only its observed inputs. These optional reference pulls are not
measured Nord resistors and do not qualify hardware startup or the full uploader.

Static continuation contract (not executed by these uploader cases)
Independent PC-relative literal decoding of both hash-checked CODE sections
agrees with reference/sharc-source-equivalence.json. Counts are 32-bit words;
the original uploader sends 384 kernel words, then count-384 from source+1536.

Transport 1's remainder precedes transport 0's kernel. The next readiness reads
are c0134998/c00052ac (bank 3 mask 2 HIGH), then transport 0's remainder follows.
Final reads wait for mask 2 LOW at c01349cc/c00052e0 and mask 8 LOW at
c01349d8/c00052ec. Only then do actual SET halfword stores release mask 4
followed by mask 1 at c01349f0/4 and c0005304/8. These instruction/operand facts
constrain future coupled execution; no current test claims those later phases.

The legacy single-peer fixture supplies explicit known-low inputs on unconnected
bank3 pads (mask fff3); the paired reference removes its four wire endpoints
from that mask (fff0). The production link supplies none. ARM currently requires every
requested GPIO-read bit to be known, even if later code masks it; the fixture
does not establish Nord pull levels or partial-bit ARM propagation. ARM is held
at its diagnosed missing-input boundary while the kernel runs. Sampling begins
after the producer becomes known. There is no claim of continuous parallel
uploader execution, completed streams, FLAG-clear/release, physical timing,
cold boot, synth/audio or acceptance under objective.txt. Separate scheduled
references now interleave the original first wait and kernel initialization
under explicit latch/cadence inputs; their narrower evidence and retained
unknown-input frontier are documented in board-scheduler.txt.
