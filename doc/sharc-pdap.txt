PDAP acquisition and core FIFO reference

SharcPdap owns the PDAP slice of the IDP interface: CTL0 at24b0, PP_CTL
at24b1, CTL1 at24b2, CTL2 at24b3, DAI_STAT0 at24b8 and FIFO at24d0.
The explicit HWR B-17 reset words are0/0/0000ffff/0. Other mapped holes,
DAI_STAT1 index-pointer behavior, SIP and DMA remain unsupported. Unsupported
DMA/ping-pong or globally active SIP configuration rejects; it never reports
a successful unimplemented channel. This is a component, not a complete IDP.

The owner supplies DAI_PB20..1 or AMI_ADDR23..4 as twenty-bit value/knowledge
pairs, plus optional clock and HOLD levels. PP_SELECT chooses the source;
observations on the other input cannot acquire data. Global IDP_EN, PDAP_EN
and channel0 enable must all be set. PP enable alone cannot receive. Required
unknown clock/history/HOLD/unmasked data fails atomically. An inactive edge
establishes known clock history; repeated levels do not add samples. Rising
and falling acquisition edges are supported. HOLD high preserves partial
packing and ignores acquisition edges, including unknown data on those edges.
Zero mask bits force zero through the documented data mask, not guessed pads.

HWR12-10..13/19 defines packing, with input data aligned to the MSB pins:

  4x8:   input19..12 -> bits7..0,15..8,23..16,31..24 in acquisition order
  3-way: input19..10 ->9..0, then19..9 ->20..10 and31..21
  2x16:  input19..4 ->15..0, then31..16
  1x20:  input19..0 ->31..12; low12 bits are zero

PDAP words retain all32 payload bits; SIP channel/LR tags are not overlaid.
Only a complete word enters the eight-word FIFO. Core reads remove exactly
one oldest word. The circular queue preserves order across wrap; zero is valid
data. Core writes provide the documented debug-injection path. The board
owner must give core writes priority over a coincident external word arrival;
this API does not resolve physical event timestamps on its own. Incoming full-
FIFO words are dropped and set channel0 overflow, without corrupting queued
data. FIFO occupancy drives STAT0 bits31..28; overflow is bit8. DMA status
stays inactive because enabling that engine is explicitly unsupported.

NSET0..7 raises a level request while occupancy exceeds N;8..15 disables that
request. Overflow remains sticky after reads create space. A real completed
DAI-latch read may acknowledge it through acknowledge_overflow. The component
does not synthesize a DAI controller, mask, vector or ISR. Threshold disappears
only when its condition disappears. IRQ controller coupling remains required.

PP_RESET is W1S/read0 and discards only partial packing. CTL1 FFCLR clears
the FIFO/size, preserving overflow. CTL0 CLROVR clears FIFO and overflow;
both command bits read0. Disabling global IDP schedules the documented two-
CCLK flush; data/status observations during that unsettled interval reject.
The owner supplies actual elapsed core clocks. HWR12-27 requires one input
SCLK after enable before receiving: advance_sclk supplies actual completed
input periods. Zero does not settle startup. Acquisition inside the unresolved
startup period rejects; physical PCLK/4 synchronization/phase still needs a
clocked board model. No Hz, source clock or elapsed period is invented.

Readiness queries distinguish valid FIFO payload/space in enabled parallel
mode. Empty reads and full core writes with BHD0 require an actual core wait;
the present IOP bridge does not yet implement that coupling and explicitly
fails instead of returning fictitious data. BHD1 empty/full values/effects,
partial-word reconfiguration without reset and some intermediate command
timing remain unqualified. These are emulator gaps to fix for stock firmware,
not claims that silicon rejects legitimate operations. PDAP strobe timing,
SIP, DMA/ping-pong and DAI_STAT1 remain mandatory future work.

MemoryDevice transactions stage controls and FIFO push/pop. External clocks,
inputs, acknowledgements and snapshots reject active transactions. Outputs
refer to committed state. Validated snapshots retain raw controls, both input
histories, partial samples, ordered FIFO, startup/flush remainders and overflow.
Unused queue storage is canonical internal representation, not a claim of
erased silicon FIFO storage. Normal acquisition/queue work uses fixed state
and does not allocate. Failed target pop/CPU retirement are separate events:
backend abort restores FIFO data; a completed external pop is cached by the
bridge and is never repeated after a later CPU destination-bank failure.

Owned tests use independent literal pack results, both edges, unknown/masked
data and HOLD, source selection, threshold/overflow/wrap, commands, delayed
disable, partial restore, transactions and malformed states. Actual native
core reads through the bridge receive data produced by observed owned input
edges; target/CPU fault repair retains exactly-once FIFO consumption.

The optional original reference executes four more actual instructions after
its60-instruction routing prefix: PP_CTL read, two real SETs and PP_CTL store.
The actual write establishes800ff000. The original global IDP_EN remains0,
FIFO/partial/IRQs remain empty and all physical inputs remain unknown. No data
or period is injected. After that posted store drains, the next actual read
of SRU2_PIN0 at1c10 remains unsupported, at PCs1c5c42/1c5bca/1c0809/1c06d5.
Explicit5/8-clock inputs give193 bridge clocks including that failed read.
CPU/IAB/SYSCTL/SPI and prior routing state are checked. This is instruction-
order evidence; full five-stage boot, board links and instrument acceptance
in objective.txt remain unchanged and incomplete.
The separate clocked application fixture now maps the DPI routers and executes
this read and both following RMW groups; its next SPI binding gap is described
in sharc-dpi.txt. The earlier instruction-order fixture remains separate.
