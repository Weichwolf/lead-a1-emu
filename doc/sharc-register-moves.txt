Native SHARC universal-register transfers

The native Type5a SISD UREG transfer uses PGR rev2.4 9-22..24 and the
actual field diagram10-9, with register codes in10-32. Source bits6:2 reside
in native bits42:38 and source bits1:0 in32:31. Destination bits6:0 reside
in29:23. Bit30 is reserved, not another source bit. COND is37:33. Swap and reserved fields remain guarded; SIMD transfer is rejected
before a false PEx condition could hide an implicit PEy operation.

A false SISD condition reads no source or destination bank. The instruction
captures the source before writing its destination through the existing UREG
interfaces. Register knowledge is preserved, not replaced by guessed values.
The existing effective MODE1 selects data/DAG banks, and Bx writes still load
Ix. SREG destinations retain their existing write/latency/readonly contracts;
unimplemented selectors fail with native PC/opcode context. Transfers do not
implicitly compute or change arithmetic flags when COMPUTE is empty.
Single-instruction loops still guard Type5; longer bodies use the common decoder.

Data-file-to-DAG/SREG and DAG/SREG-to-data-file moves transfer upper32 bits,
aligned at bits39:8 of the data register. Such32-bit writes clear low8.
Transfers between data-file registers copy all40 value/known bits, including
Rx/Sx crossings and fractional extension bits, independent of RND32. Explicit
Sx accesses in SISD use their own PEy register bank; they imply no PEy compute.
Combined-PX/data40 and split-PX/UREG32 moves retain sharc-px.txt's contract.
Combined-PX with parallel compute, swap and SIMD pairing remain guarded.

Parallel compute
A nonempty COMPUTE23 executes through the same qualified ALU/shifter decoder
as Type2a. The original SISD condition controls both operations. All transfer
source values are captured before compute writes/flags; compute then executes
and the captured UREG destination write commits. This is one guest instruction,
not two retired instructions or a host arithmetic substitute.

PGR2-6..7 explicitly gives UREG writes precedence over computational results.
A simultaneous DREG destination conflict therefore retains the transferred
value, while flags still describe the computation. A transfer from ASTAT
captures its old flags. Bx still updates Ix, and MODE1 writes keep their existing
one-following-instruction effect delay. Unsupported compute or a failed final
register write rolls back computation, source/destination/control and pending
effects together. Explicit ASTAT writes remain unsupported; no write is dropped.
Primary references:2-5..7,3-3/5,4-98/Table4-40,9-22..24,10-9,A-14/17..20.

sharc_register_moves uses literal encodings for data/B/I/USTAT/explicit-Sx
transfers, split source fields, partial knowledge, Bx-to-Ix side effects,
zeroed extension bits, preserved flags, false conditions/unknown banks,
secondary DAG selection, MODE1 effect latency and failed-mode/field rollback.
The actual kernel I0=R3 and USTAT2=R2 execute in all four original placements
without a special PC/opcode callback (sharc-arithmetic.txt).

sharc_parallel_register_moves checks8192 source/destination/PE/bank/RND32/
partial-knowledge combinations, including extension bits and self copies;
literal compute/move encodings; old-source dependence; UREG-over-compute write
priority with retained computation flags; old ASTAT capture; Bx/Ix side effects;
delayed bank selection; pending-control rollback after tentative compute;
false predicates and unsupported compute. No random fuzz or physical timing claim.

The optional direct original stream reference executes R9=PASS R12 with
R11=old R9 at all four placements and both fixed serial cadences. Its independent
finalizer expectations retain the old instruction template in R11 and original
SYSCTL value in R9; arithmetic DO remains unsupported (sharc-stream-reference.txt).
