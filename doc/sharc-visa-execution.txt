Captured VISA instruction execution reference

Sharc::step(SharcVisaBuffer&) executes the actual complete captured word
through the existing CPU/memory/device transaction. Internal decoding maps
qualified compact fields into existing operation fields; neither instruction
RAM nor its captured encoding changes. SharcStep reports that original
encoding and its address_units. Sequential PC uses1/2/3 short words; native
execution still uses one normal word. Missing input, wrong PC/memory and
unqualified instructions fail with the captured address and execution context.

The IAB consumption is staged before CPU execution and published only after
successful CPU/RAM/device commit. Failure retains every input and resource.
Taken immediate redirects flush speculative input even when the destination
equals the sequential address. Actual delayed JUMP/RTS slots advance by each
captured instruction's length before the pending target takes effect. CALL
pushes the actual following address; RTS uses the real26-bit frame. A taken
VISA CALL(DB) remains guarded until its two slot lengths are retained. A false
condition does not push or require unused slot metadata. Native delayed CALLs
retain their original two native slots and may target the VISA reference.

Qualified compact forms: Type1b/3b/4b/5b data-only forms; Type2b packed
compute; Type17b signed16 immediate; Type2c short integer add/sub/pass/compare/
not/inc/dec/and/or/xor and floating add/sub/multiply; Type3c DM transfer;
Type11c plain/delayed conditional RTS; Type21c NOP. Corresponding native
operand/mode/memory/rounding guards remain. Other compact operations, RTI,
IDLE and arithmetic-loop entry remain explicit gaps. The bounded VISA
counter-loop form is a single uncompressed48-bit body: PGR4-54/55 requires
short-loop bodies to remain uncompressed. Begin/end increments use the real
short-word length; native counter behavior retains its one-word default.
General mixed-width loops, PC-stack DB arbitration and cache timing are open.

This API is an instruction-order reference, not the five-stage native/VISA
fetch/branch connection. Buffer capture/Decode events remain explicit owner
inputs. It does not certify global clocking, automatic cache/port grants or
hardware timing. The clocked native/VISA transport is qualified separately in
sharc-fetch-visa.txt; the complete common call remains open.

Owned tests use literal mixed encodings,64 signed-immediate/register edge
cases,13 independent short-compute results, three ordered/equal compact COMP
flag/history outcomes, actual compact dual/DM stores,
real CALL/RTS frames, immutable captured returns, same-address redirects,
mixed-length delayed slots, native CALL/VISA RTS, a real single48-bit loop,
foreign ownership and read-only-store repair through separately bound state.
No instruction decoder output is its own expected result.

original_sharc_visa_instructions freshly verifies all originals and runs the
same candidate-response native prefix. It retains a CPU/transport checkpoint
before independently exercising the clocked JUMP/first CALL, then forks from it and
executes the real JUMP/CALL/common clock prefix in instruction order. Each
placement/cadence must retire8286 actual instructions, including one native
JUMP, one compact RTS and8256 actual NOPs at six independent wait addresses
(16/4096/16/4096/16/16). Eleven real PMCTL accesses finish at control40012,
settled divider40000 and the actual return to entry+3 with an empty stack.
The checkpoint CPU/transport, SYSCTL and all ordinary payload cells remain
checked. No PC/opcode is invented and tag1 is never turned into host zero-fill.
The zero NOPs come from the original RAM-clear/alias history.

This reference supplies only instruction minimum-clock bounds to PMCTL, with
equal stable CLKIN counts while bypassed. Ratios18/9/36/5 are modeled relative
to the explicit CLKIN input; no physical frequency or board phase is inferred.
It does not qualify full clocked execution or a full boot.
The subsequent second-call power/modifier prefix and64-instruction PBEN/clock/
frame/PP_CTL reference are qualified separately in sharc-power.txt,
sharc-dai-enable.txt, sharc-dai-timing.txt and sharc-pdap.txt. The next target
is unmapped SRU2_PIN0. The initializer is incomplete;
full instrument acceptance remains unchanged.

Primary constraints: PGRrev2.4 4-5/9,4-16/23,4-54/55,9-62/63,10-5/29,
11-94,12-12. The later SHARC+ reference rev1.5 16-17/18 and26-1 explicitly
lists the shared Type17b/imm16visa signed range for five-stage cores; only that
compatible operand definition is used, never SHARC+ pipeline timing.
Provenance and factual source-only corroboration are in reference/sharc.json.
